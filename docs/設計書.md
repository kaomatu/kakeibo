# 家計簿アプリ 設計書

## 1. 概要

個人利用を前提とした、入力が速く、状況をひと目で把握できる家計簿アプリ。
Android ネイティブアプリ（Expo / React Native）と Web アプリから利用し、Firebase を共通のバックエンドとする。

### 設計方針

- 最短の操作で支出・収入を登録できることを最優先とする。
- 情報量を絞り、金額の状態は色と符号でも直感的に伝える。
- データは利用者本人だけがアクセスできる。
- リアルタイム監視は行わない。アプリ起動時、画面復帰時、手動更新時にサーバー上のデータを取得する。

## 2. 技術構成

| 領域 | 採用技術 | 用途 |
| --- | --- | --- |
| Android | Expo / React Native | ネイティブアプリ |
| Web | Expo Router による Web 対応 | PC ブラウザ向け画面 |
| 認証 | Firebase Authentication | 個人ログイン |
| データベース | Cloud Firestore | 取引、カテゴリ、予算などの保存 |
| 定期取引の生成 | Cloud Functions for Firebase または起動時のクライアント処理 | 未作成の定期取引を作成 |
| グラフ | React Native / Web 対応のチャートライブラリ | 月次推移・カテゴリ比較 |

初期のログイン方式は **Google ログイン** を採用する。必要になった場合はメールアドレス・パスワード認証を追加できる。

## 3. 画面構成

| 画面 | 目的 | 主な内容 |
| --- | --- | --- |
| ログイン | 本人確認 | Google ログイン |
| ダッシュボード | 現在の状況確認 | 今日・今月の支出、今月の残予算、最近の取引、登録ボタン |
| 取引登録 | 支出・収入の記録 | 種別選択、カテゴリ、金額、日付、支払い方法、メモ |
| 取引一覧 | 履歴確認・編集 | 新しい順のタイムライン、検索、絞り込み、編集・削除 |
| 分析 | 月ごとの振り返り | カテゴリ比較、月次推移グラフ |
| 予算 | 月の予算管理 | カテゴリ別予算、合計予算、使用額、残額 |
| 定期取引 | 継続する取引の管理 | 家賃・給与・サブスクの追加、変更、停止 |
| 設定 | マスターデータ管理 | 支出／収入カテゴリ、支払い方法、同期・ログアウト |

モバイルでは下部タブを「ホーム」「取引一覧」「分析」「設定」とし、常時表示する「＋ 登録」ボタンを置く。Web では同じ項目をサイドナビゲーションに表示する。

## 4. 機能要件

### 4.1 取引登録

登録操作は以下の順序とする。

1. 「＋ 登録」を押す。
2. 「支出」または「収入」を選ぶ。
3. カテゴリと金額を入力する。
4. 必要に応じて日付、支払い方法、メモを入力して保存する。

| 項目 | 必須 | 仕様 |
| --- | --- | --- |
| 種別 | 必須 | `expense`（支出）または `income`（収入） |
| カテゴリ | 必須 | 選択した種別に属する有効なカテゴリから選択 |
| 金額 | 必須 | 1 円以上の整数 |
| 日付 | 必須 | 初期値は当日。過去日を指定可能 |
| 支払い方法 | 必須 | 初期値を設定可能（例：現金） |
| メモ | 任意 | 検索対象となる短い自由入力 |

保存後はダッシュボードまたは直前の一覧へ戻り、保存完了を短く通知する。

### 4.2 取引一覧

- 取引を日付の降順、同日内では作成日時の降順でタイムライン表示する。
- 日付ごとに区切り、支出は赤系、収入は青系で種別を判別できるようにする。
- 取引を選択すると編集・削除できる。
- 削除時は確認ダイアログを表示する。削除は論理削除ではなく Firestore 上の取引データを削除する。

絞り込み条件は組み合わせて利用できる。

- 期間（今月、先月、任意範囲）
- 種別（支出／収入）
- カテゴリ
- 支払い方法
- 金額範囲
- メモのキーワード検索

### 4.3 カテゴリ管理

- 支出用・収入用を分けて追加、名称変更、並べ替え、削除できる。
- カテゴリ削除は過去の取引を変更しない「アーカイブ」として扱う。
- アーカイブ済みカテゴリは新規登録の候補に出さない。
- 過去の取引・分析では、`削除済み：{カテゴリ名}` と明示して表示する。
- カテゴリを削除する前に、対象の取引件数を表示して確認を求める。

### 4.4 月次集計・分析

- 選択した月の支出、収入、収支を表示する。
- 支出カテゴリごとに、選択月と比較対象月の金額差・増減率を表示する。
- 比較対象月の初期値は先月とし、利用者が任意の月へ変更できる。
- 月ごとの支出、収入、収支を線グラフで表示する。
- カテゴリの表示順はカテゴリ管理で設定した順序を基本とする。

### 4.5 予算管理

- 支出カテゴリごとに、対象月の予算額を設定する。
- 月の総予算はカテゴリ予算の合計として自動計算する（別途入力しない）。
- 各カテゴリおよび月全体で、予算・使用額・残額・消化率を表示する。
- 残額が 0 以上なら青色と `+`、超過なら赤色と `-` を用いる。
- 予算を設定していないカテゴリはグレーで「予算未設定」と表示する。

### 4.6 定期取引

- 毎月の家賃、サブスクリプション、給与などを自動作成できる。
- 設定項目は種別、カテゴリ、金額、支払い方法、実行日、メモ、有効状態とする。
- 既存設定の金額・カテゴリ・実行日・メモを変更できる。
- 停止した設定からは以降の取引を生成しない。過去に作成済みの取引は保持する。
- アプリ起動時の同期処理で、当日以前かつ未作成の有効な定期取引を作成する。
- 重複生成を防ぐため、取引には生成元の定期取引 ID と対象年月を保存する。

### 4.7 ダッシュボード

表示項目は以下に限定する。

- 今日の支出
- 今月の支出、収入、収支
- 今月の残予算
- 予算超過または残額が少ないカテゴリ
- 最近の取引（最新 5〜10 件）
- 「＋ 登録」ボタン

### 4.8 同期

- アプリ起動時に Firestore から必要な最新データを取得する。
- バックグラウンドから復帰した場合も同様に同期する。
- 画面上で手動更新できる。
- Firestore のリアルタイムリスナーは常時接続しない。
- オフライン時は最後に取得したローカルデータを表示し、同期できていないことを通知する。

## 5. データ設計（Cloud Firestore）

利用者ごとのデータを `users/{uid}` 配下に完全に分離する。

```text
users/{uid}
  profile
  categories/{categoryId}
  paymentMethods/{paymentMethodId}
  transactions/{transactionId}
  budgets/{yyyy-MM}/items/{categoryId}
  recurringTransactions/{recurringTransactionId}
```

### 5.1 profile

| フィールド | 型 | 内容 |
| --- | --- | --- |
| displayName | string | 表示名 |
| createdAt | timestamp | 作成日時 |
| defaultPaymentMethodId | string | 既定の支払い方法 ID |

### 5.2 categories

| フィールド | 型 | 内容 |
| --- | --- | --- |
| name | string | カテゴリ名 |
| type | string | `expense` または `income` |
| sortOrder | number | 表示順 |
| isArchived | boolean | 削除済み（アーカイブ）フラグ |
| archivedAt | timestamp/null | アーカイブ日時 |
| createdAt / updatedAt | timestamp | 作成・更新日時 |

### 5.3 paymentMethods

| フィールド | 型 | 内容 |
| --- | --- | --- |
| name | string | 例：現金、クレジットカード、電子マネー |
| sortOrder | number | 表示順 |
| isArchived | boolean | 新規入力候補から除外するフラグ |

### 5.4 transactions

| フィールド | 型 | 内容 |
| --- | --- | --- |
| type | string | `expense` / `income` |
| amount | number | 金額（円、正の整数） |
| date | string | `YYYY-MM-DD`、集計基準日 |
| categoryId | string | カテゴリ ID |
| categoryNameSnapshot | string | 削除後も表示するための登録時名称 |
| paymentMethodId | string | 支払い方法 ID |
| paymentMethodNameSnapshot | string | 表示用名称 |
| memo | string | 任意メモ |
| recurringTransactionId | string/null | 定期取引から生成された場合の ID |
| recurringPeriod | string/null | 重複防止用の `YYYY-MM` |
| createdAt / updatedAt | timestamp | 作成・更新日時 |

### 5.5 budgets/{yyyy-MM}/items/{categoryId}

| フィールド | 型 | 内容 |
| --- | --- | --- |
| categoryId | string | 支出カテゴリ ID |
| amount | number | 月次予算（円） |
| updatedAt | timestamp | 更新日時 |

### 5.6 recurringTransactions

| フィールド | 型 | 内容 |
| --- | --- | --- |
| type | string | `expense` / `income` |
| categoryId | string | カテゴリ ID |
| amount | number | 金額 |
| paymentMethodId | string | 支払い方法 ID |
| dayOfMonth | number | 実行日（1〜31） |
| memo | string | 任意メモ |
| isActive | boolean | 有効／停止 |
| createdAt / updatedAt | timestamp | 作成・更新日時 |

## 6. 集計ルール

- 対象月は取引の `date` を基準に判定する。
- 支出合計は `type = expense`、収入合計は `type = income` の取引金額を合計する。
- 月間収支は `収入合計 - 支出合計` とする。
- カテゴリ残額は `カテゴリ予算 - 当月カテゴリ支出` とする。
- 月間残予算は `全カテゴリ予算合計 - 当月支出合計` とする。
- アーカイブ済みカテゴリの取引も、履歴・集計・グラフに含める。

## 7. 認可・セキュリティ

- Firebase Authentication で認証済みの利用者だけが利用できる。
- Firestore Security Rules で、`users/{uid}` 配下への読み書きは `request.auth.uid == uid` の場合だけ許可する。
- クライアントから他ユーザーのパスを指定してもアクセスできないルールにする。
- 金額は正の数値、種別は定義済みの値に限定するバリデーションをクライアントと Security Rules の両方で行う。

## 8. MVP 範囲

最初のリリースでは、以下を実装対象とする。

1. Google ログイン
2. 取引の登録・編集・削除
3. 取引タイムライン、検索、絞り込み
4. カテゴリ・支払い方法管理
5. ダッシュボード
6. カテゴリ別予算と残額表示
7. 起動時・復帰時・手動のデータ同期

月次分析のグラフと定期取引は、データ設計を先に含めた上で MVP 後に追加する。
